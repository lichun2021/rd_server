# Heroes 1116-1122 Runtime Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Tasks are sequential because they share battle core classes and `ConstProperty`.

**Goal:** Complete trustworthy server-side runtime skill behavior for new expedition heroes 1116, 1118, 1120, and 1122 without inventing combat formulas.

**Architecture:** Port hero-specific skill registration, effect checkers, state objects, and the smallest required battle-engine hooks from the newer `E:\rd_new` server source. Keep configuration closure and runtime closure separate; office heroes 1115, 1117, 1119, 1121, and 1123 remain on generic non-march effects.

**Tech Stack:** Java 8-era Gradle project, Protocol Buffers, XML configuration, Python `unittest` closure tests.

**Spec:** Conversation-approved plan from 2026-08-22; no separate design document.

## Global Constraints

- Never overwrite whole battle core files from `E:\rd_new`; port only hero-specific hunks into the current `rd_server` versions.
- Never invent damage formulas, probabilities, target selection, stacking, caps, or round boundaries from client text.
- Keep `GameServer/xml` and the worktree test copy of `Publish/xml` synchronized for changed XML.
- Preserve existing numeric protocol IDs; adapt newer-source enum names such as `EFF12721` to this repository's `HERO_12721`.
- Do not modify the main worktree's ignored `Publish` directory or its log4j files during implementation.
- Each production behavior starts with a failing test and ends with the focused test plus the existing hero closure suite passing.
